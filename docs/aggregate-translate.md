## 聚合翻译插件（office-translate-pro）

参考并模仿 GitHub 开源项目 **[UlionTse/translators（翻译官）](https://github.com/UlionTse/translators)**（2.6k+ Star）实现：

- **多引擎聚合**：Bing / 阿里 / 有道（百度、DeepL 等引擎在库中同样可用，当前默认取质量与稳定性最优的三个），自动降级重试，无需任何 API Key
- **自动分段**：按 900 字符（优先保留段落/换行边界）切分后逐段翻译并合并，支持长句长文（实测 9300+ 字符正常翻译）
- **文件翻译**：支持 UTF-8 / GBK 文本文件，结果保存为 `<文件名>_to_<语言>.txt`（保存目录跟随工具箱"设置→保存路径"）
- **短文本**：≤900 字符直接在面板内返回译文

用法：插件管理 → 加载"聚合翻译"→ 选择文件（或输入文本）→ 选择目标语言/引擎 → 开始翻译；长文完成后系统通知并指明结果文件。

## 工程要点（维护迭代补充）

- **依赖懒加载**：`translators` 首次 `import` 需联网拉取引擎配置（实测 10~35 秒），而宿主 `plugin.init` 超时为 15 秒——早期把它放在模块顶层会导致**首次加载必然超时**并误触发"自愈重装依赖"。现已改为**首次实际翻译时懒加载**（带锁防并发重复导入），实测 `plugin.init` 由 12s 超时 → **0.06s** 成功。
- **stdout UTF-8**：插件启动即 `sys.stdout.reconfigure(encoding='utf-8')`，避免在 GBK 环境下被第三方拉起时 JSON 解析失败。
- **无用的 `_shared.screen_capture` 导入已移除**（会拖慢启动且未被使用）。

其余翻译插件（中英互译/多语言/批量文件）保留，聚合翻译为增强全能版；批量文件翻译已支持**逐行容错**（单行失败保留原文继续）与**每 50 行中间落盘**，避免限流中断导致整批结果丢失。
