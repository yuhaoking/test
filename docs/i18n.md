# 国际化（T-12）

> 目标语言：**简体中文 / 繁體中文 / English / 日本語**。设置 → 通用 → 界面语言，默认「跟随系统」。

## 一、这一版做到了什么（以及没做到什么）

**做到了**——决定"非中文用户能不能用起来"的那一层外壳：

| 位置 | 状态 |
| --- | --- |
| 托盘菜单（含勾选项、修复窗口提示、更新提示） | ✅ 四语言 |
| 宠物右键菜单 | ✅ 四语言 |
| 系统通知（崩溃已隐藏 / 已自动恢复 / 最小化到托盘） | ✅ 四语言 |
| 桌面工作台（左栏、卡片标题、上下文标签、动作提示、文件页签） | ✅ 四语言 |
| 命令面板搜索占位符 | ✅ 四语言 |
| 设置：导航项 + 语言选择器 | ✅ 四语言 |
| 侧边栏按钮标题 | ✅ 四语言 |
| **其余页面正文（设置各分区、剪贴板、市场、开发者工具、插件输出）** | ❌ **仍是中文** |

**没做到的原因**：全仓有 **1683 行**非注释的含中文代码（90 个文件）。逐条翻译成 3 种语言不仅工作量大，
更关键的是**质量不可控**——机器翻译出来的设置页文案，比中文原文更糟。所以这一版的目标是"骨架先通"：
基础设施 + 外壳 + 可量化的增量路线。

任何时候都可以用这条命令看到真实进度：

    npm run i18n

它会给出"还剩多少行含中文"，以及剩余最多的文件（下一轮优先级）。

## 二、怎么加一条文案

1. **只在 `shared/i18n/messages.ts` 的 `ZH_CN` 里新增**，key 用 `域.用途` 命名（如 `deskboard.card.music`）；
2. 同步补 `EN` 与 `JA` —— **漏一个 `npm test` 会直接变红**，不会等到用户切语言才发现；
3. `zh-TW` **不用手写**：由 `shared/i18n/hant.ts` 从 zh-CN 转换生成；
4. 界面里用 `t('your.key')`，带参数写 `t('your.key', { n: 3 })`，占位符是 `{n}`。

主进程里从 `electron/services/i18n.ts` 取 `t`；渲染层从 `src/i18n.ts` 取。

## 三、繁体为什么不是"逐字替换"

机械逐字转换会产出半简半繁的怪东西：

- 「复制」→「**復**制」（正确是「複製」）—— 一字多形，逐字必错；
- 「设置」→「設置」（台湾习惯是「**設定**」）—— 字形对但用词不对；
- 「文件」→「文件」（台湾叫「**檔案**」）、「剪贴板」→「剪贴板」（台湾叫「**剪貼簿**」）。

所以 `hant.ts` 的策略是**先词表、后字表**：

1. `PHRASES`：两岸用词差异 + 一字多形词（复制→複製、文件夹→資料夾、窗口→視窗…）；
2. `CHARS`：逐字兜底（幽灵→幽靈、暂无→暫無…）；
3. `ZH_TW_OVERRIDES`：少数仍需人工定夺的整条覆写。

**字表是怎么来的**（这一步不能省）：把字典里出现的每个汉字跑一遍转换，逐个人工确认"没变化"的字里
哪些其实是简体独有。只凭直觉写，实测漏了 21 个 —— 包括「幽灵→幽灵」「暂无→暂無」这种一眼假的错误。
现在 `npm test` 里有一条不变式：**转换结果不得残留任何"字表声明为简体独有"的字**，新增文案时漏字会立刻变红。

**诚实边界**：这是"可读的繁体"，不等于"台湾本地化文案"。词表已覆盖本应用高频词，
长尾用语建议由母语者通过 `ZH_TW_OVERRIDES` 覆写完善——改文案不用改逻辑。

## 四、行为约定

- **默认跟随系统**：`zh-Hant-TW / zh-HK / zh-MO` → 繁體；`ja-*` → 日本語；`en-*` → English；其余 → 简体中文；
- **设置脏值不炸**：`locale` 被手工改成非法值时回退"跟随系统"，界面永远打得开；
- **切换立即生效**：渲染层 `t()` 内部读 `locale` 这个 ref，模板会自动重渲染（冒烟测试真开设置页断言过"通用 → General"）；
  主进程的托盘菜单是"构建时快照"，所以在设置变更的副作用里显式重建；
- **缺 key 显示 key 本身**（如 `tray.showMain`），而不是空白 —— 漏翻译要一眼可见；
- 窗口 `<html lang>` 会随语言更新（影响字体选择与断行）。
