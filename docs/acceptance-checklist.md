## 已知边界


- **进度拖动依赖播放器端 SMTC**：网易云/Spotify/酷狗支持 seek；QQ 音乐 PC 新版忽略 `TryChangePlaybackPositionAsync`（会提示"该播放器暂不支持拖动进度"），播放/暂停/上下曲不受影响
- **点击封面进入的是"当前正在播放"的应用**（按 SMTC 会话判断）
- Office 转换优先走 Office COM，其次 LibreOffice/Pandoc/Poppler/Tesseract；缺失引擎时插件会给出可读提示
- DeepSeek 相关能力（对话/余额/用量管家/AI 造插件）需要真实 `sk-` API Key，仅保存在本机
- 歌词来自 QQ 音乐公开接口，未收录曲目显示"暂无歌词"
- 翻译走公共接口（`translators` 聚合 Bing/阿里/有道 或 Google→MyMemory 降级），需联网
- 划词翻译用**模拟 Ctrl+C** 取词，因此依赖前台应用支持复制；取词期间会短暂占用剪贴板（已抑制历史记录并在取词后恢复）
- 录屏默认只录主屏；录制不含声音
- `openPath` 会启动用户显式点选的程序（应用启动器固有行为，已限制为存在的路径 + 外链仅 http/https/mailto）
- SQLite 后端需 Electron ABI 二进制（`@electron/rebuild` + `npmRebuild: true`），否则自动回退 JSON 后端（功能一致）
- **两个性能门槛余量极薄，跑 bench 会偶发翻红（不是回归）**：CP-03 首屏实测 P50 193~196 / P95 197~198ms（门槛 200ms，余量 2~7ms），5 次复跑中有 1 次出现 P95 200.1ms（超 0.1ms）；T-01 空闲 CPU 实测 0.95~0.98%（门槛 <1%）。二者都是“遍历 + 拼音匹配”与“后台监听”的固有成本，且在机器上有 `npm run dev` 等其它负载时就会被推过线。判读规则：**复跑一次仍红才算回归**；后续若再往首屏链路加任何同步工作，必须先扩预算或改异步补全
- **主题包不含代码能力**（设计如此）：只允许图片与文本，导入端会拒绝任何可执行内容；需要代码的场景走插件体系
